📌 1. Users (Пользователи)
Связь: Один пользователь может добавить много ссылок (URL).

Как реализовано: в таблице Urls есть поле UserId, которое указывает на Users.Id.

📌 2. Groups (Группы)
Связь: В одной группе может быть много ссылок (URL).

Как реализовано: в таблице Urls есть поле GroupId, которое указывает на Groups.Id.

📌 3. Urls (Ссылки)
Связь: Одна ссылка принадлежит одному пользователю и одной группе. При этом одна ссылка ведет на один товар.

Как реализовано:

UserId → Users.Id (кто добавил).

GroupId → Groups.Id (куда добавил).

На эту ссылку ссылается таблица Product через поле UrlId.

📌 4. Product (Товары)
Связь: Один товар спарсен с одной ссылки (URL). У одного товара может быть много записей истории цен.

Как реализовано:

UrlId → Urls.Id (с какой ссылки спарсен).

На этот товар ссылается таблица PriceHistory через поле ProductId.

📌 5. PriceHistory (История цен)
Связь: Каждая запись истории принадлежит одному товару.

Как реализовано: ProductId → Product.Id (к какому товару относится).

Итог (цепочка):
Пользователь → создает Группу → добавляет в нее URL → парсит с него Товар → пишет его Историю цен.
